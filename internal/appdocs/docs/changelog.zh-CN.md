# 升级日志

## v0.1.35 (2026-11-22)

- ACP 会话更稳定：进程退出不再依赖 stdout EOF，避免会话被永久卡在等待；取消或长时间无回包的轮次会在超时后收口，不再一直显示「运行中」。
- 在途工具增加最大存活期：超龄工具按失败收口并回到就绪，避免个别工具挂起拖住整个会话。
- 连接与握手更耐用：同 key 的已死连接不再复用而是重建；握手超时先自动重试一次再降级到终端；Cursor 握手超时放宽到 240 秒以覆盖 MCP 初始化；MCP 服务正确回显客户端协议版本，修复 Cursor 的 ACP 握手超时。
- 轮次状态更透明：桌面端展示轮次超时的具体原因，窗口重新聚焦时主动对账会话状态；ACP 会话状态变化通过 `chat:status` 主动推送，界面不再滞后。
- 修复 Claude 别名与模型名写入问题：别名和裸模型名不再写入 `ANTHROPIC_MODEL`，恢复会话时不再回放别名；会话内 `/model` 使用 CLI 无法解析的模型名会被拦截并给出中英文提示；别名槽位空缺时自动补齐，避免回落到内置真模型名导致 400；会话内切换模型能力恢复。
- 文件树与 Git 面板刷新更及时：展开目录会主动刷新直接子目录并先作废旧缓存；Git 面板订阅仓库变更；同步按钮改为先获取再同步，避免在落后远端时直接推送。
- 降低桌面端常驻内存：收敛文件监视缓冲。
- OpenCode 会话关联更完整：桌面端持久化应用级 LLM 会话 ID，AgentHub、Git 提交信息生成与微信桥请求都会携带 `x-opencode-session` 会话头。

## v0.1.34 (2026-11-20)

- 微信语音更可靠：支持 Opus 编码语音；格式无法解码时回执会指明实际格式（AMR/MP3/M4A/OGG 等）并保留原始文件便于排查；转写模型拒答时明确提示「未能转写，文件已保存，发文字后一并转交」，不再把拒答文本当成转写结果。
- 新增本地语音转写：AgentHub 设置页新增「本地语音转写」卡片，可一键安装 sherpa-onnx 引擎（非内置，自动镜像下载、SHA256 校验、断点续传，安装过程显示阶段与百分比进度）；语音优先本地转写，未安装或失败时自动回退云端。
- 微信附件队列 1 分钟超时惰性过期：只发附件没有配文字时，之后不会任意时刻弹出「请指定目标会话」的待选菜单。
- 语音转写成功后音频不再作为附件入队，避免被智能路由降级为「指定目标会话」待选。
- ACP 会话瞬时失败自动续跑一轮（桌面端默认开启）：按本轮 stderr 增量识别瞬时错误，续跑期间取消与退出有守卫，长时间任务不再因一次网络抖动而中断。
- AgentHub 管理者能识别「等待回答」的会话：agent 消息以问号结尾时，用户随后的回答默认回投该会话，不再误判为新需求而反问或群发；查询进度、叫停任务这类请求改为直接汇报或执行，不再多余投递。
- 修复微信「附件 + 文字」合并回答在 AgentHub 反问挂起时被直接投到无关会话的问题：有挂起反问时合并回答走续跑，没有挂起时转「待选」，绝不直投当前会话。
- 修复本地语音安装时自死锁导致新建会话、会话预览等操作整体卡住的问题。

## v0.1.33 (2026-11-18)

- 统一默认工具与模型：桌面端新建会话、微信 `#en` 与 AgentHub 派发统一使用 AgentHub「⚙ 默认设置」里的默认工具与模型；未显式选择时不再按「会话最多/列表第一个」随手挑，改用的默认值不可用时才会回落到首个已安装的 ACP 工具。
- AgentHub 新建会话的默认项目改为最近使用的项目；OpenCode 新建会话会沿用上次选择的模型，不再落到 big-pickle。
- 修复微信智能路由失败时消息被静默投递到当前会话的问题：路由失败现在一律转为「待选」并回执原因，避免投错会话或多路投递；关闭 AgentHub 时仍保持原有的直接投递语义。

## v0.1.32 (2026-11-18)

- 升级更稳：检测到新版本后先下载并校验当前平台的安装包，确认可用才提示「新版本已就绪」；点「稍后」会保留已下载的包，下次启动或再次检查直接复用，不再重复下载。
- 升级提示只在安装包真实可用时出现：最新版本若尚未提供当前平台的安装包，不会提示升级，也不会错误地提示更旧的版本。
- 设置页检查更新会区分「下载并安装」与「安装并重启」：安装包未下载时先下载校验，已就绪则直接安装；已就绪的包在断网时也能安装。
- npx 一键安装：最新版本拿不到当前平台安装包时，自动回退安装上一个发布版本。
- 修复 Windows 上「重启应用」在 PowerShell 5.1 环境启动失败、退出后无进程的问题。

## v0.1.31 (2026-11-18)

- AgentHub 管理者的反问支持直接答复：思考链中出现询问卡时，可在卡片内完成单选、多选或自由文本回答，提交后管理者自动续跑，无需再到会话里手动追问；答复进度实时显示并可中断，微信端同样支持。
- 反问表单体验增强：支持多步问卷向导（确认步无选项时自动回落为是/否）；选择「Other」时按需展开文本框；卡片标题显示所属项目与会话；卡片可点击收起，已答复的卡片有明确状态，多选为空时禁用提交。
- 管理者思考链按轮分组折叠展示，长任务不再一长条铺满聊天区；管理者会参考最近会话消息与项目、会话语境，减少空转式的重复推理。
- 修复取消或模型异常停止（拒答、达到最大 token 等）后，进行中的工具长期停留在 running、导致前端队列卡死的问题。
- 修复 AgentHub 新建会话入口可选择不支持 ACP 的工具、创建后无法对话的问题；不支持的工具已自动过滤。
- AgentHub 输入框中的纯数字回答不再被当作命令：正在等待反问答复时，直接回数字即视为作答。
- 微信绑定整合进 AgentHub 设置：关闭 AgentHub 会自动解绑微信并同步首页显示；关闭前二次确认，关闭后迟到的扫码结果不会再写回凭据；解绑与扫码流程顺序化，修复遗留绑定与孤儿轮询。
- Git 提交框新增 AI 生成提交信息：基于已暂存改动生成单行 `type: 简述` 并一键回填，本地与 SSH 远端仓库均支持；diff 异常或远端限流时给出明确提示，不再把 git 报错文本当作改动交给模型。
- 聊天表单（elicitation）兼容 `anyOf` 枚举，代理工具返回的联合类型选项可正常解析与展示。

## v0.1.30 (2026-11-16)

- 文件树支持复制/剪切/粘贴：Ctrl+C 复制选中文件到系统剪贴板（资源管理器可直接粘贴），Ctrl+X 树内剪切后粘贴即移动；粘贴到目标目录时重名自动加序号改名不覆盖，移动到自身子目录会被拒绝。
- 设置页新增 AgentHub 区块：总开关、心跳阈值与宿主同步集中管理；WorkBuddy 可一键同步 kshell 操作能力，其它宿主提供自助安装指引（生成 `~/.kshell/host-install.md`，把界面上的一句话指令发给平台 AI 即可自动完成安装）。
- AgentHub 管理者升级为大模型驱动的循环 agent：支持工具调用与 ask 续轮确认，带长期记忆（落盘 journal 与搜索），并自动注入最近会话消息作为上下文；桌面 Hub 与微信桥均已接入，管理者的思考过程与结论落盘可见，「继续」类捷径直达等待中的会话。
- 新增 `kshell agent` 命令族与本地 HTTP API：可发现/创建会话、投递消息、订阅输出，供 WorkBuddy 等外部宿主以编程方式操作 kshell。
- 新增 WorkBuddy 模型平台：设置页导入 WorkBuddy 凭据后，聊天经本地代理直连 WorkBuddy 网关，可直接使用其提供的模型（自动完成协议翻译与流式合成）。
- 模型平台支持按工具独立选择：可为 codex / gemini 等工具单独指定模型平台，各处模型下拉统一为「先选平台再选模型」；聊天内切换模型只影响当前会话，不再回写全局默认。
- AgentHub 新增群发与总览命令：`#g` 多会话群发、`#st` 逐会话状态总览、`#gx` 按会话回看最近消息；无明确目标时由本地模型智能路由投递，长任务聚合为心跳行并在全部结束后自动汇总报告，微信端同样生效。
- ACP 聊天窗口底部操作行并入模型与参数选择器；窗口内发消息改为直投，不再被 AgentHub 路由阻塞。
- 修复 ACP 长任务时间线停摆的问题（事件种子窗口未关闭导致后续更新丢失）。
- 聊天页性能优化：时间线组件 memo 化，长会话打字不再重渲染全部消息，消除输入卡顿。
- 修复扫描期磁盘会话被抢绑给同工作区无主旧聊天的错绑问题。
- 提交日志加载失败时弹出错误提示，不再静默空白。
- 移除聊天页「换个说法」快捷回复；Claude 平台不再向下拉注入 default 伪模型。
- AgentHub 发送链路重做：明确指定了目标的消息（在会话对话页直接发、@ 某个会话、回复编号、引用消息）一律直接投递，不再先交给本地模型「分析该发给谁」——此前这些消息会被模型重新路由，出现多发一次模型往返、甚至把消息转投到别的会话的问题。同时下线了 AgentHub 的本地工具循环与其写操作确认卡（需求/会话工具改为只在「无目标自由文本」的意图路由中使用）。
- 输入路由收敛为两档：「自动」与「仅 agent」，原来的「强制工具」已无独立含义，旧配置自动按「自动」处理。
- AgentHub 发送即时反馈：没有明确目标时，用户气泡与「思考中」气泡会立刻出现并逐步显示当前阶段（判断目标 / 正在投递 / 列出会话），等待期间可点「中断」中止本次分发——此前要等模型首 token 返回才突然出现内容，看起来像没发出去。
- 文件树不再因按住 Shift 插入复选框（输入大写字母时整树会横向漂移），多选改为 Shift 区间选 + Ctrl/Cmd 点击逐个加选/取消。
- 模型同步改为按工具定制：设置页工具行的「同步平台模型」开关升级为「模型设置」页——Claude Code 按 4 类映射槽位（默认模型 / Sonnet / Opus / Haiku）勾选模型，OpenCode 按平台勾选（支持多平台并存），CodeBuddy 勾选默认平台模型；未启用或未勾选任何模型时不注入，并清理既有注入物。注意：升级后此前自动注入的全量模型会被清掉，请在各工具的「模型设置」里重新勾选。
- 设置页「设为默认」平台与「默认模型」选择即时生效，不再依赖整包保存按钮；由此触发的模型同步做了防抖合并，连续切换只同步一次。
- 会话模型下拉与注入物同口径：各工具只列出该工具实际可用的模型（claude 为默认平台模型，opencode/codebuddy 为勾选模型），不再出现选了也走不通的假选项。
- 模型设置页改左右布局：平台列表在左，新增/编辑平台的表单在右侧展开，保存按钮移入表单内，保存后自动收起；「启用同步」开关与「删除平台」也改为即时生效，不再依赖独立保存按钮。
